# API v1 — the contract kept by the rebuild

The endpoints below are used by the web page, `client/pyurlabuse` and external
integrations. The rebuild (see `doc/ROADMAP.md`) reimplements them with the
same requests and answers. `tests/contract/` checks them against a running
instance.

**Since the rebuild**, the v1 endpoints are a thin layer on the providers
(`website/web/legacy.py` for the routes, a flask-restx namespace documented as
"API v1 (legacy)" in `/swagger.json` and on the `/api` page, `urlabuse/legacy.py` for the jobs,
run by the `analysis_worker`): same requests, same answers. Sources that are
not ported yet answer "not configured" (empty body); `/whois` answers `null`
(no contact found) until WHOIS is ported. New clients should use API v2: every v1 endpoint has a v2 equivalent
(table in `doc/api/v2.md`, "From API v1 to API v2").

All `POST` bodies are JSON (the `Content-Type` is not checked). Every check is
asynchronous: the `POST` returns a **job id as plain text**, then the client
polls `GET /_result/<job id>`.

## Jobs

| Endpoint | Answer |
|---|---|
| `POST /<check>` | `200`, body = job id (UUID, text). **Empty body** = the source is not configured (no API key): the client must skip it. |
| `GET /_result/<job id>` | `202` + `"Nay!"` while pending · `200` + JSON result when done (the job is then deleted: a second call answers `null`) · `200` + `null` for an unknown id |

A job that fails in the worker never gets a result: it stays `202` until the
client gives up.

## Checks

| Endpoint | Body | Result (JSON, once the job is done) |
|---|---|---|
| `POST /start` | `{"url": u}` | `[true, url, null]` or `[false, url, reason]`. `url` is normalised (`hxxp` → `http`, `http://` added when there is no scheme). Also counts the submission of the day (auto-report to CIRCL past a threshold). |
| `POST /urls` | `{"url": u}` | list of the URLs of the redirect chain (HTTP redirects and `meta refresh`, max 5 levels), in order, without duplicates |
| `POST /resolve` | `{"url": u}` | `[ipv4 list or null, ipv6 list or null]` |
| `POST /lookyloo` | `{"url": u}` | Lookyloo permalink of the capture (string) or `null` |
| `POST /phishtank` ¹ | `{"query": u}` | PhishTank detail page URL or `null` |
| `POST /virustotal_report` ¹ | `{"query": u}` | `[verbose_msg, permalink, positives, total]` or `null` |
| `POST /googlesafebrowsing` ¹ | `{"query": u}` | Google Safe Browsing verdict text or `null` |
| `POST /eupi` ¹ | `{"query": u}` | EUPI tag label or `null` (the URL is submitted to EUPI when unknown) |
| `POST /pdnscircl` ¹ | `{"query": u_or_ip}` | `[number of hostnames, first 5 hostnames]` |
| `POST /psslcircl` ¹ | `{"query": ip}` | `{sha1: [certificate subjects]}` or `null` |
| `POST /bgpranking` | `{"query": ip}` | `[asn, prefix, asn_description, rank, position, total_known_asns]`, all `null` when unknown |
| `POST /whois` | `{"query": u_or_ip}` | list of abuse e-mails (after the ignore/replace lists) or `null` |
| `POST /urlquery`, `POST /ticket` | `{"query": u}` | **Disabled**: the old code is commented out, they answer `404` today (pyurlabuse still calls them). The rebuild answers an empty body ("not configured"), see `AGENTS.md` decision 12. |

¹ Needs credentials; empty body when they are missing.

## Report

| Endpoint | Body | Answer |
|---|---|---|
| `POST /get_cache` | `{"query": u, "digest": bool}` | `{"result": [{url: {check: result, ip: {check: result}}}, …]}` for the URL and each URL of its chain; with `digest: true`, also `"digest": [text, [abuse e-mails], ["AS description (asn)"]]` |
| `POST /submit` | `{"url": u}` | sends the digest + JSON by e-mail to CIRCL, at most once a day per host; answers the home page HTML. Since the rebuild: `503` (JSON) when reports are not enabled on the instance (`report` in `config/generic.json`) |
| `GET /urlreport` | `?url=` | HTML report page. Since the rebuild: redirects to `/?url=…`, the home page that checks the URL |
| `HEAD /` | — | `200` when the website is up (`pyurlabuse.is_up`) |

In the `get_cache` result, the check keys are: `valid`, `list`, `dns`,
`lookyloo`, `phishtank`, `vt`, `gsb`, `eupi`, `whois` on URLs, and `ipasn`,
`bgpranking`, `pdns`, `pssl`, `whois`, `phishtank` on IPs.
