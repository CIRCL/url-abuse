# API v2 — the broker

Mounted at `/api/v2`. The description is generated by flask-restx
(`/swagger.json`, Swagger 2.0) and shown in two places:

- **`/api`**, the API page of the site (linked as "API" in the header of every
  page and in the footer of the home page): `templates/api.html` renders the
  description with `<vt-openapi variant="full">` from
  [vitrine](https://github.com/ecrou-exact/vitrine) (search, schemas, example
  requests with `<vt-http>`, Markdown descriptions with `<vt-markdown>`).
  `static/api.js` loads the vitrine modules and points them at their files;
  `app.css` maps our colour and font tokens onto vitrine's `--vt-*` tokens, so
  the reference follows the light and dark themes of the site.
- The description has two groups (tags): **API v2** and **API v1 (legacy)**
  (doc/api/v1.md).
- **`/doc/`**, the stock Swagger UI of flask-restx (linked from `/api`).

Vitrine is not committed: `tools/3rdparty.py` downloads the source of a pinned
commit (SHA-256 checked), builds it with Node >= 20 and installs it in
`static/vendor/vitrine/` (git-ignored). See `doc/install.md`.

## Analyse a URL

```bash
curl -X POST -H 'Content-Type: application/json' -d '{"url": "https://example.com/login"}' \
     https://<instance>/api/v2/analyse
# 201 {"uuid": "…", "url": "https://example.com/login"}
curl https://<instance>/api/v2/analyse/<uuid>      # poll until status is done or failed
```

`POST /api/v2/analyse` `{"url": …}`: `201 {"uuid", "url"}` (the URL as it is
checked: trimmed, `hxxp` fixed, `http://` added when there is no scheme), or
`400` when the URL can't be checked (not http/https, no host, too long).

`GET /api/v2/analyse/<uuid>` (`404` when unknown or expired, after 7 days):

```json
{
  "uuid": "…", "url": "http://github.com", "status": "done",
  "created": 1791886591.0, "finished": 1791886650.0, "error": null,
  "progress": {"done": 4, "total": 4},
  "lookyloo": {"status": "ok", "links": ["https://lookyloo…/tree/…"], "data": {"redirects": […]}, …},
  "chain": [
    {"url": "http://github.com",
     "results": {"dns": {"status": "ok", "data": {"host": "github.com", "ipv4": ["140.82.121.4"], "ipv6": []}, …}},
     "hosts": [{"ip": "140.82.121.4", "family": "IPv4",
                "results": {"bgpranking": {"status": "ok", "data": {"asn": "36459", …}, …}}}]},
    {"url": "https://github.com/", …}
  ],
  "verdict": {"verdict": "unknown", "flagged_by": [], "checked_by": []},
  "providers": {"dns": {"label": "Addresses", "reputation": false}, …}
}
```

- `status`: `queued`, `running`, `done` or `failed` (`error` says why).
- `chain`: the checked URL, then the URLs it redirects to (from the Lookyloo
  capture); each with the answer of every URL provider, and the answers of
  every IP provider for each address of its host.
- each answer is a `ProviderResult` (doc/providers.md): `status` (`pending`
  while it runs), `data`, `verdict`, `links`, `error`, `cached`.
- `verdict`: from the reputation providers (doc/architecture/jobs.md).

How it runs: doc/architecture/jobs.md.

## One provider at a time

`POST /api/v2/providers/{name}/query` `{"value": …}` (URL, hostname or IP):
`201 {"uuid"}`, `404` for an unknown provider. Then
`GET /api/v2/queries/{uuid}`: `{"uuid", "provider", "value", "kind",
"status": "queued" | "done", "created", "finished", "result"}` where `result`
is the `ProviderResult` once done (`not_configured` / `not_applicable` when
the provider can't answer). Kept a day, readable many times. Run by the
`analysis_worker` (`urlabuse/queries.py`).

## Validate a URL

`POST /api/v2/validate` `{"url": …}` → `200 {"valid", "url", "reason"}`: can
it be checked, and the URL as it would be checked. Immediate, nothing queued.

## Cached results

`POST /api/v2/cached` `{"url": …, "digest": false}`: everything still in the
provider cache about the URL and its chain, in the shape of an analysis
(`url`, `lookyloo`, `chain` with `results` and `hosts`), without querying
anything; answers expire with each provider's `cache_ttl` (DNS: one hour). With
`"digest": true`, also `digest: {"text", "abuse_contacts", "asns"}`, the text
sent to CIRCL.

## From API v1 to API v2

Everything API v1 does has a v2 equivalent (the v1 descriptions in the API
reference say which):

| v1 | v2 |
|---|---|
| `POST /start` | `POST /api/v2/validate` (and `POST /api/v2/analyse` to check it) |
| `POST /urls` | `POST /api/v2/providers/lookyloo/query` → `data.redirects` (or `chain` of an analysis) |
| `POST /lookyloo` | `POST /api/v2/providers/lookyloo/query` → `data.permalink` |
| `POST /resolve` | `POST /api/v2/providers/dns/query` |
| `POST /bgpranking` | `POST /api/v2/providers/bgpranking/query` |
| `POST /whois`, `/phishtank`, `/virustotal_report`, `/googlesafebrowsing`, `/eupi`, `/pdnscircl`, `/psslcircl` | `POST /api/v2/providers/{name}/query`, once ported (`GET /api/v2/providers`) |
| `POST /urlquery`, `/ticket` | none (sources gone) |
| `GET /_result/{job_id}` | `GET /api/v2/queries/{uuid}` (or `GET /api/v2/analyse/{uuid}`) |
| `POST /get_cache` | `POST /api/v2/cached` |
| `POST /submit` | `POST /api/v2/report` |
| `GET /urlreport?url=` | `/?url=` (web page) or `POST /api/v2/analyse` |

## Report to CIRCL

`POST /api/v2/report` `{"url": …}`: e-mails the results of the URL to CIRCL
analysts (`report.recipients` in `config/generic.json`), built from the cached
answers (check the URL first). At most once a day per host:
`200 {"sent": true}` or `200 {"sent": false}` when the host was already
reported today; `503` when reports are not enabled on the instance
(`report.enabled`), `400` for an invalid URL. The web page shows the "Send
report to CIRCL" button only when reports are enabled. A URL submitted
`report.autosend_threshold` times in a day through v1 `/start` is reported
automatically (as before). Code: `urlabuse/report.py`.

## Providers

`GET /api/v2/providers`: name, label, description, kinds of values taken
(`url`, `hostname`, `ip`), whether it gives a verdict (`reputation`) and
whether it is configured on this instance.

## Health

`GET /api/v2/health` → `200 {"status": "ok", "database": true, "version": …}`,
or `503` with `"status": "degraded"` when Valkey is unreachable.

## Errors

Every error under `/api/` (and for any client whose `Accept` header prefers
`application/json`) is JSON:

```json
{"status": 404, "error": "Not Found", "message": "The requested URL was not found on the server…"}
```

Other requests get the error page (`templates/error.html`): code, title,
message, a link to the home page and to the API documentation. 404, 405 and
500 have their own wording (`ERROR_MESSAGES` in `website/web/__init__.py`);
an unhandled exception is logged and answered as a 500.
